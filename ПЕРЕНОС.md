# Как перенести BankInvest на другой компьютер

Этот документ — для случая «работает у меня, нужно показать преподавателю на ноутбуке».
Три варианта, от самого простого к самому основательному. Выберите **один**.

| Вариант | Что нужно на ноутбуке | Плюсы | Минусы |
|---|---|---|---|
| **A. Docker** | Docker Desktop | 2 команды, ничего не настраивать, база в контейнере | нужен Docker и ~2 ГБ на образ |
| **B. Обычный SQL Server** | SQL Server Express/Developer + Node.js | работает как у вас, привычные инструменты | один раз проходит настройку |
| **C. Комплект-архив** | Node.js | всё в одном файле, работает без интернета | SQL Server всё равно нужен (вариант B внутри) |

Рекомендация: если на ноутбуке **есть интернет** — вариант **A** (самый быстрый), если **нет** — вариант **C** плюс заранее установленный SQL Server Express.

---

## Вариант A. Docker — самый быстрый

Поднимает SQL Server 2022 и сервер BankInvest в двух контейнерах. Схема и демо-данные
загружаются автоматически при первом старте.

### Что нужно
1. Установить **Docker Desktop** для Windows: https://www.docker.com/products/docker-desktop/
   При установке оставить галочку «Use WSL 2». После установки перезагрузиться.
2. Скопировать на ноутбук папку проекта (или архив из варианта C).

### Запуск

В командной строке в папке проекта:

```cmd
docker compose up -d
```

Первый запуск занимает 3–5 минут (скачиваются образы). Затем:

```cmd
docker compose ps
```

Должно быть два контейнера в состоянии `running` (у `bankinvest-app` — `healthy`).

Открыть в браузере: **http://localhost:8787/**

Вход: вкладка **ID организации** → `100200300` / `client123`.

### Остановка и данные

```cmd
docker compose stop     # остановить, данные сохранятся
docker compose start    # снова запустить
docker compose down     # удалить контейнеры, данные в томе останутся
docker compose down -v  # удалить всё вместе с данными
```

### Если что-то не так

```cmd
docker compose logs -f app        # журнал сервера
docker compose logs -f sqlserver  # журнал базы
```

| Симптом | Причина | Решение |
|---|---|---|
| `port is already allocated` | занят порт 1433 или 8787 | закройте локальный SQL Server или поменяйте порт в `docker-compose.yml` |
| `app` перезапускается | база ещё не поднялась | подождать 1–2 минуты, `docker compose restart app` |
| `Docker Desktop is starting` | Docker ещё грузится | дождаться значка «Engine running» |

### Про десктопную версию и Docker

Десктоп (WinForms) работает только на Windows и подключается к серверу по HTTP.
Он **не** запускается в контейнере, но отлично работает с контейнерным сервером:
`BankInvest.exe` → «Сервер:» → `http://localhost:8787` → OK.

## Вариант B. Обычный SQL Server

Так проект работает у вас сейчас.

### Что установить на ноутбуке

| Программа | Ссылка | Зачем |
|---|---|---|
| SQL Server Express (или Developer) | https://www.microsoft.com/sql-server/sql-server-downloads | база данных |
| SQL Server Management Studio (SSMS) | https://aka.ms/ssms | восстановить базу, выполнять запросы |
| Node.js 18+ (LTS) | https://nodejs.org | сервер и веб-версия |
| .NET 8 SDK — *по желанию* | https://dotnet.microsoft.com/download/dotnet/8.0 | только для сборки/запуска десктопа из исходников |

### Шаг 1. Включить TCP/IP и порт 1433

Без этого сервер Node.js не подключится к базе.

1. **SQL Server Configuration Manager** → **SQL Server Network Configuration** →
   **Protocols for MSSQLSERVER** (или `for SQLEXPRESS`) → **TCP/IP** → правой кнопкой **Enable**.
2. Двойной клик по **TCP/IP** → вкладка **IP Addresses** → раздел **IPAll**:
   `TCP Port = 1433`, поле `TCP Dynamic Ports` — пустое.
3. Перезапустить службу от администратора:
   ```cmd
   net stop MSSQLSERVER & net start MSSQLSERVER
   ```
   (для Express: `net stop "MSSQL$SQLEXPRESS" & net start "MSSQL$SQLEXPRESS"`)
4. Проверить: `Test-NetConnection localhost -Port 1433` → `TcpTestSucceeded : True`.

### Шаг 2. Восстановить базу с вашими данными

В комплекте есть файл **`BankInvest.bak`** — это ваша рабочая база: клиенты, бумаги,
транзакции, история цен. Восстанавливается одной командой.

**Способ 1 — автоматически (рекомендуется).** В папке проекта:

```cmd
set MSSQL_USER=sa
set MSSQL_PASSWORD=ваш_пароль_sa
БЫСТРЫЙ-СТАРТ.bat
```

Скрипт сам спросит логин/пароль, восстановит базу из `BankInvest.bak`, применит
актуальную схему (таблица `Sessions`, процедуры, право `EXECUTE`) и запустит сервер.

Если нужно только восстановление:

```cmd
cd server
npm install
npm run db:restore
```

**Способ 2 — вручную через SSMS.**

1. Положите `BankInvest.bak` в папку, доступную службе SQL Server, например
   `C:\Program Files\Microsoft SQL Server\MSSQL16.MSSQLSERVER\MSSQL\Backup\`.
2. SSMS → правой кнопкой по **Databases** → **Restore Database…** →
   **Device** → **…** → **Add** → выбрать `BankInvest.bak` → **OK**.
3. Вкладка **Files**: если путь подсвечен красным — поменяйте каталог на существующий.
4. **OK**. Затем откройте `db\schema.sql` и нажмите **F5** — файл сам выберет базу
   и дополнит её до текущей версии.

> **Важно про `.bak`:** если SSMS при «Add» выдаёт ошибку 3241 «Отсутствует порядковый номер
> семейства: 2», это значит, что копия писалась **в два файла**, а у вас только первый.
> Нужен второй файл (обычно `BankInvest2.bak` рядом) — либо просто создайте базу скриптами:
> ```cmd
> cd server
> npm run db:init
> ```
> Это даёт ту же структуру (13 таблиц, процедуры, права) и демо-данные.

> Если `.bak` нет или он не подходит — создайте базу с нуля:
> ```cmd
> cd server
> npm run db:init
> ```
> Это схема + демо-данные (13 клиентов, 18 бумаг, история цен).

### Шаг 3. Указать логин и пароль приложения

```cmd
setx MSSQL_USER sa
setx MSSQL_PASSWORD "ваш_пароль"
```

Закройте окно командной строки и откройте новое — переменные читаются при старте.

> Для презентации проще всего использовать `sa`. Если политика безопасности не
> позволяет — создайте отдельный логин (см. `README_RU.md`, раздел «SQL Server»):
> ```sql
> CREATE LOGIN bankinvest WITH PASSWORD = N'Пароль123', CHECK_POLICY = OFF;
> USE BankInvest;
> CREATE USER bankinvest FOR LOGIN bankinvest;
> ALTER ROLE db_datareader ADD MEMBER bankinvest;
> ALTER ROLE db_datawriter ADD MEMBER bankinvest;
> ALTER ROLE db_ddladmin   ADD MEMBER bankinvest;   -- для обновления процедур
> ```

### Шаг 4. Проверить и запустить

```cmd
cd server
npm run db:check
```

Ожидается: `Подключение : OK`, `Таблицы : все 13 на месте`, обе процедуры «есть,
право EXECUTE выдано», итог «Всё готово». Затем:

```cmd
npm start
```

Веб-версия: **http://localhost:8787/**

### Шаг 5. Десктопная версия (по желанию)

**Если есть .NET 8 SDK:**
```cmd
dotnet run
```

**Если SDK нет** — используйте готовую сборку из папки `desktop\`:
запустите `desktop\BankInvest.exe`. Если адрес сервера другой, в окне входа нажмите
«Сервер:» и укажите `http://localhost:8787`, OK (адрес запоминается).

> Готовую сборку создаёт `tools\make-kit.bat` на компьютере, где установлен .NET 8 SDK
> (флаг `--self-contained true` — .NET на ноутбуке не потребуется).

## Вариант C. Комплект-архив (работает без интернета)

### Как собрать комплект — на вашем компьютере

```cmd
tools\make-kit.bat
```

Появится файл `BankInvest_перенос_ГГГГ-ММ-ДД.zip`, внутри:

```
BankInvest/
├── БЫСТРЫЙ-СТАРТ.bat        ← запускать этот
├── db-setup.bat             восстановить базу / создать заново
├── ПЕРЕНОС.md               эта инструкция
├── README_RU.md             полное описание проекта
├── BankInvest.bak           ваша база с данными (если файл был в папке)
├── desktop\BankInvest.exe   готовая десктопная версия (если был .NET SDK)
├── server\                  веб-версия + API, уже с node_modules
├── db\                      schema.sql, seed.sql
├── *.cs, BankInvest.csproj  исходники десктопа
├── docker-compose.yml       вариант с Docker, если он есть на ноутбуке
└── docs\                    архитектура и описание API
```

`server\node_modules` включён специально: на ноутбуке **не нужен интернет** для `npm install`.

### Как развернуть — на ноутбуке

1. Распаковать архив, например в `C:\BankInvest`.
2. Установить SQL Server Express (см. вариант B, шаг 1) — если его ещё нет.
3. Двойной клик по **`БЫСТРЫЙ-СТАРТ.bat`**.
4. Ввести логин и пароль SQL Server (обычно `sa`) — скрипт сохранит их для следующих запусков.
5. Скрипт сам: восстановит базу из `.bak`, проверит её, запустит сервер и откроет браузер.

Всё. Повторный запуск — снова `БЫСТРЫЙ-СТАРТ.bat` (логин уже сохранён).

## Ошибка `ELOGIN` / «Login failed» (вход отклонён)

Это **не** проблема сети: порт 1433 уже открыт (`TcpTestSucceeded : True`), сервер отвечает.
SQL Server отклонил сам вход. Три причины и порядок проверки:

1. **Сервер в режиме «только Windows».** По умолчанию SQL Server принимает только
   Windows-вход, а приложение ходит под SQL-логином (например `sa`) — его не пускают.
   Лечение: SSMS → правой кнопкой по серверу → **Свойства** → **Безопасность** →
   **«Режим проверки подлинности SQL Server и Windows»** → **перезапуск службы**.
2. **Неверный пароль** или логин отключён.
3. **Логина ещё нет** в этой базе.

Самый быстрый путь — выполнить в SSMS файл **`db/create-app-login.sql`** (F5).
Он включает смешанный режим, создаёт логин `bankinvest` с паролем `BankInvest!2026`
и выдаёт права. После этого:

```cmd
net stop MSSQLSERVER & net start MSSQLSERVER   :: перезапуск службы (нужен администратор)
setx MSSQL_USER bankinvest
setx MSSQL_PASSWORD "BankInvest!2026"
```

и **новое** окно командной строки (setx меняет переменные только для новых окон).

Проверить, каким входом вы сейчас работаете в SSMS:

```sql
SELECT SUSER_NAME() AS Вход, SERVERPROPERTY('InstanceName') AS Экземпляр;
```

Если вернулось `DESKTOP-XXX\tazik` — это Windows-вход, и SQL-логины, скорее всего, запрещены.

## Ошибка «НЕ НАЙДЕНЫ: Sessions» (база из старого `.bak`)

`Подключение: OK`, но `db:check` пишет `Таблицы: НЕ НАЙДЕНЫ: Sessions`.

**Что значит.** База была создана до того, как общий сервер стал хранить сессии
в SQL Server. Таблицы `Sessions` тогда не было — она нужна серверу, чтобы веб-версия
и десктоп входили по одному токену и не разлогинивались при перезапуске.

**Лечение (одна команда, данные не затрагиваются):**

```cmd
cd server
npm run db:init
```

> **Если `db:init` остановится с сообщением «нет права ALTER»** — это нормально:
> `schema.sql` пересоздаёт процедуры (`DROP` + `CREATE`), а логин приложения
> не создавался для изменения структуры. Выполните в SSMS под администратором
> файл **`db/grant-ddl.sql`** (F5) и повторите `npm run db:init`.
> Право выдаётся роли `db_ddladmin` — ровно столько, сколько нужно для схемы.

`schema.sql` идемпотентен: недостающее создаёт, существующее не трогает,
процедуры пересоздаёт. Демо-данные при этом **не** загрузятся повторно — скрипт
видит, что клиенты уже есть.

Альтернатива без командной строки: откройте **`db/schema.sql`** в SSMS и нажмите **F5**
(файл сам выбирает базу `BankInvest`).

> Начиная с этой версии сервер при старте сам проверяет наличие всех 13 таблиц
> и, если чего-то не хватает, применяет `schema.sql` автоматически
> (`BANKINVEST_AUTO_UPGRADE=0` отключает это поведение).

## Первый запуск на чистом ноутбуке — по шагам

Если на ноутбуке ещё ничего не установлено, порядок такой:

1. **Проверить, что есть.** Двойной клик по **`ПРОВЕРКА-СИСТЕМЫ.bat`** — покажет Node.js,
   .NET, службу SQL Server, состояние порта 1433 и самой базы.
2. **Установить Node.js** (если в проверке «НЕ НАЙДЕН»): https://nodejs.org → кнопка **LTS**.
   При установке оставить галочку **Add to PATH**. После установки закрыть все окна cmd.
3. **Установить SQL Server Express** (если нужно) и включить TCP/IP (вариант B, шаг 1).
4. **Если `npm run db:check` пишет `[ESOCKET] Failed to connect ... :1433`** — выполнить
   `npm run sql:doctor` (в папке `server`): покажет, отвечает ли порт, запущена ли служба,
   какие экземпляры установлены, и выдаст готовые команды `net start`, `setx MSSQL_INSTANCE`.
5. **Запустить `БЫСТРЫЙ-СТАРТ.bat`** — он найдёт Node.js сам (даже если PATH не обновился),
   поставит драйвер, спросит логин/пароль SQL Server, подготовит базу и запустит сервер.
6. Если нужна десктопная версия без установки .NET — запускать `desktop\BankInvest.exe`
   из комплекта (собирается на компьютере с .NET 8 SDK).

> Команды `npm run ...` рассчитаны на то, что **Node.js установлен и окно cmd открыто заново**.
> Если `npm` «не является внутренней или внешней командой» — это не ошибка проекта,
> а отсутствие Node.js в системе (или старое окно).

## Что показать преподавателю

Порядок демонстрации на 3–4 минуты:

1. **Веб-версия**: http://localhost:8787/ → вход `100200300` / `client123` (ID организации).
2. **Мои активы** → «Купить» → выбрать предложение → купить 1–2 бумаги.
3. **SSMS**, запрос — покупка уже в базе:
   ```sql
   USE BankInvest;
   SELECT TOP 5 t.Id, c.Name, s.Symbol, t.Type, t.Quantity, t.Price, t.Commission, t.[Date]
   FROM Transactions t
   JOIN DepoAccounts d ON d.Id = t.DepoAccountId
   JOIN Clients c ON c.Id = d.ClientId
   JOIN Securities s ON s.Id = t.SecurityId
   ORDER BY t.Id DESC;
   ```
4. **Десктоп** (`desktop\BankInvest.exe` или `dotnet run`) → вход `employee` / `emp123` →
   «Транзакции»: та же покупка из веб-версии видна в десктопе.
5. Главная мысль для ответа: *оба приложения — тонкие клиенты одного REST API,
   все данные и бизнес-правила (покупка) живут в SQL Server, процедура `usp_BuyListing`
   выполняет сделку одной транзакцией.*

## Если что-то не работает

| Сообщение / симптом | Что значит | Что делать |
|---|---|---|
| `db.connect ... Failed to connect to localhost:1433` или `[ESOCKET]` | SQL Server недоступен: служба не запущена, выключен TCP/IP, другой порт или это именованный экземпляр (`SQLEXPRESS`) | запустить `npm run sql:doctor` — он проверит порт, службы и экземпляры и напишет точную команду; подробно — вариант B, шаг 1 |
| `[ELOGIN]` / 18456 «Login failed» | **не** сеть: порт открыт, но SQL Server отклонил вход — режим «только Windows», неверный пароль или логина нет | выполнить в SSMS `db/create-app-login.sql` (создаёт `bankinvest`, включает смешанный режим); см. раздел «Ошибка `ELOGIN`» выше |
| `db.login` | неверный логин/пароль | `setx MSSQL_PASSWORD "…"` и **новое** окно cmd |
| `db.permission` | нет прав (в т.ч. `EXECUTE` на процедуры) | выполнить `db\schema.sql` (F5) — он выдаст права |
| `НЕ НАЙДЕНЫ: Sessions` | база создана раньше текущей схемы (например, из старого `.bak`) | `npm run db:init` — данные не пострадают, добавится только `Sessions` |
| «нет права ALTER» / `[3701]` при `db:init` | логин приложения не может пересоздавать процедуры | выполнить в SSMS `db/grant-ddl.sql`, затем снова `npm run db:init` |
| `Таблицы : НЕ НАЙДЕНЫ` | база не создана/восстановлена | `npm run db:restore` или `npm run db:init` |
| «Купить» выдаёт ошибку прав | нет `EXECUTE` на `usp_BuyListing` | `db\schema.sql` (раздел 8) или `GRANT EXECUTE` вручную |
| Порт 8787 занят | уже запущен другой сервер | закрыть старое окно или `set PORT=8790` |
| Десктоп: «Не удалось подключиться к серверу» | сервер не запущен или другой адрес | `npm start`, затем в окне входа указать `http://localhost:8787` |
| `"npm" не является внутренней или внешней командой` | Node.js не установлен **или** окно cmd открыто со старым PATH | закрыть окно, открыть новое. Если не помогло — установить Node.js (галочка «Add to PATH»). Батники проекта (`БЫСТРЫЙ-СТАРТ.bat`) находят Node сами |
| Скрипт не находит `node` | Node.js не в PATH | переустановить Node.js с галочкой «Add to PATH» или запускать через `БЫСТРЫЙ-СТАРТ.bat` |

Диагностика одной командой:

```cmd
cd server
npm run db:check
```

## Частые вопросы

**Нужен ли интернет на ноутбуке?**
Для варианта C — нет (кроме установки SQL Server и Node.js, которые лучше поставить заранее).
Для варианта A — только на первый запуск, пока скачиваются образы.

**Можно ли поменять пароль `sa` на ноутбуке?**
Да, задайте новый в SQL Server и выполните `setx MSSQL_PASSWORD "новый"` в новом окне cmd.

**Что если на ноутбуке уже установлен SQL Server со своей базой?**
Ничего не конфликтует: программа использует базу с именем `BankInvest`, ваши базы не трогаются.

**Как сделать, чтобы база на ноутбуке была с моими данными?**
Убедитесь, что `BankInvest.bak` лежит в папке проекта перед `tools\make-kit.bat`;
`БЫСТРЫЙ-СТАРТ.bat` восстановит именно её.

**Как удалить всё, что программа создала?**
Удалить базу в SSMS (`DROP DATABASE BankInvest`), папку проекта и файл настроек
`%APPDATA%\BankInvest\server.txt`. Для Docker — `docker compose down -v`.
