# BankInvest — устройство и решения

Документ для того, кто будет проект сопровождать: что и почему сделано именно так.

## 1. Исходное состояние

Было одно приложение: WinForms (.NET 8) + SQL Server. Все запросы (44 вызова `Db.Table/Exec/Scalar`),
вся бизнес-логика (комиссия, лимиты, остатки, целевые доли) были зашиты в интерфейсные классы или
в хранимые процедуры SQL Server (`usp_BuyListing`, `usp_UpdatePrices`).

Такую систему нельзя «просто» сделать совместной: два независимых клиента (браузер и приложение),
пишущих в базу мимо друг друга, разъедутся в правилах и в правах доступа.

## 2. Целевая архитектура

```
клиенты (тонкие)  →  HTTP REST /api  →  сервер (вся логика)  →  SQLite (один файл)
```

* **Сервер — единственное место, где живут правила.** Комиссия 0,5 %, коридор цены 0,3–3 × рынок,
  проверка свободного остатка, лимит целевых долей 100 %, права (клиент видит только своё),
  расчёт NPV/IRR/PI, ежечасное изменение цен — всё в `server/src/logic.js` и `server/src/db.js`.
* **Десктоп стал «тонким клиентом».** Интерфейс не менялся, но вместо `Db.*` (ADO.NET → SQL Server)
  теперь `Api.*` (HTTP → сервер). Файл `Api.cs` — единственная точка общения с сервером.
* **Веб-версия — второй клиент того же API.** Никакой отдельной логики: те же эндпоинты, те же тексты
  (словари `i18n.json` сгенерированы из `Localization.cs`), то же оформление.
* **Совместная работа** обеспечивается двумя механизмами:
  1. общая база (по определению одно состояние данных);
  2. server-sent events `/api/events`: сервер сообщает всем клиентам «изменились данные»
     (`changed`, с логином автора) и «обновились котировки» (`prices`). Клиенты перечитывают
     открытый раздел — без опроса по таймеру и без лишней нагрузки.

## 3. Почему такие технологии

| Решение | Причина |
|---|---|
| Node.js 22+ и встроенный `node:sqlite` | нет ни одной внешней зависимости: `npm install` не нужен, сервер поднимается одной командой на Windows/Linux/macOS; файл базы легко копируется |
| SQLite вместо SQL Server | для учебного/демонстрационного банковского приложения этого достаточно; транзакции (`BEGIN IMMEDIATE`), ограничения (`CHECK`, `UNIQUE`), WAL-режим для параллельных чтений |
| REST + JSON | одинаково просто вызывать из C# (`System.Net.Http` + `System.Text.Json`, без пакетов) и из браузера (`fetch`) |
| SSE вместо WebSocket | однонаправленные уведомления «данные изменились» — именно то, что нужно; в C# читается построчно, в браузере поддерживается `EventSource`; нет рукопожатий и библиотек |
| Веб-версия без сборки (один `app.js`, без React) | проект должен запускаться «как есть», без node_modules и билд-шага; при этом используется тот же CSS-дизайн, что в WinForms |
| Токены в таблице `Sessions` | простой серверный «выход» и проверка прав на каждом запросе; токен хранится в `%AppData%\BankInvest\token.txt` (десктоп) и `localStorage` (веб) |

## 4. Безопасность и что нужно доработать для продакшена

Сделано: пароли — SHA-256 (как было в исходном приложении), проверка прав на сервере, журнал действий,
параметризованные SQL-запросы, серверные проверки всех бизнес-правил.

Намеренно не делалось (учебный проект, но перечисляю честно):

1. **HTTPS** — ставить reverse proxy (nginx/Caddy/IIS), сервер слушать на 127.0.0.1.
2. **Пароли**: перейти на PBKDF2/Argon2 с солью + миграция старых хешей.
3. **Ограничение частоты входа** (защита от перебора) и блокировка после N неудач.
4. **Роли на запись**: сейчас любой сотрудник может менять портфель любого клиента — при необходимости
   добавить проверку владельца/подразделения.
5. **Срок жизни токена** (сейчас сессия живёт до выхода) и CSRF-защита, если появится cookie-аутентификация.

## 5. Соответствие прежней логике

| Было (SQL Server) | Стало |
|---|---|
| `usp_BuyListing` | `L.buy()` в `logic.js` (та же последовательность: блокировка предложения, проверка продавца/количества, перенос бумаг, две транзакции с комиссией 0,5 %) |
| `usp_UpdatePrices` | `db.updatePrices()`: новый час = новая точка на бумагу, ограничение цены по номиналу и сегменту, затем `Price`/`PrevPrice` пересчитываются |
| `SELECT ... FROM Portfolio` в `MainForm.LoadPortfolio` | `L.portfolio()` + `recalc()` на сервере |
| Расчёт NPV/IRR/PI/Payback в `LoadProjects` | `L.projectMetrics()` |
| Отчёт за 30 дней в `LoadReport` | `L.report()` |
| Проверки в `Trading.Sell` | `L.sell()` (свободный остаток, коридор цены) |
| `Db.Audit` | `db.audit()` + событие всем клиентам |

Формулы и константы сохранены: комиссия `0.005`, коридор цены `[0.3·P, 3·P]`, IRR — бисекция 200 шагов на
интервале `[-0.99, 10]`, PI по ставке проекта, окупаемость линейной интерполяцией.

## 6. Если понадобится вернуть SQL Server

API-контракт (`docs/API_RU.md`) — это граница. Достаточно переписать `src/db.js` и запросы в
`src/logic.js` на `mssql`-драйвер: клиенты (десктоп и веб) не изменятся, потому что они ходят в API.
Альтернатива — оставить SQLite как основную базу, а в SQL Server делать периодическую выгрузку
для корпоративной отчётности.

## 7. Как расширять

* **Новый раздел**: эндпоинт в `server/src/server.js` → метод в `logic.js` → раздел в `app.js`
  (веб) и в `MainForm` (десктоп).
* **Новые тексты**: добавить пару в `Localization.cs`, затем `node tools/gen-i18n.js` —
  `server/src/i18n.json` обновится, веб-версия подхватит автоматически.
* **Новая таблица**: дописать `CREATE TABLE IF NOT EXISTS` в `migrate()` (`db.js`) — существующая
  база обновится при старте без потери данных.
