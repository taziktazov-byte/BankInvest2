# BankInvest — десктоп + веб-версия + общий сервер

Приложение «Беларусбанк — Инвестиции и ценные бумаги» теперь работает в двух видах:

| Версия | Что это | Где запускается |
|---|---|---|
| **Десктоп** | прежнее приложение WinForms (C#, .NET 8) — интерфейс, разделы и горячие клавиши не изменились | Windows |
| **Веб** | та же система в браузере: те же разделы, тот же дизайн, 3 языка, те же правила торговли | любой компьютер/телефон в сети |
| **Сервер** | один процесс Node.js: REST API + сама веб-версия + доступ к базе + live-обновления | Windows / Linux / macOS, сервер или обычный ПК |
| **База** | **Microsoft SQL Server** — прежняя схема (`Clients`, `Securities`, `Holdings`…), правила торговли в процедурах `usp_BuyListing` / `usp_UpdatePrices` | SQL Server 2017+ / Express (бесплатный) |

Главное: **у обеих версий одна база — SQL Server**. Клиент купил бумаги в браузере — сотрудник сразу
видит это в десктопном приложении (и наоборот), без перезапуска и без синхронизации вручную.
Всё, что делает десктоп и веб, записывается в те же таблицы SQL Server, поэтому изменения видны и в
SQL Server Management Studio.

```
        ┌────────────────────┐            ┌────────────────────┐
        │  Десктоп (WinForms)│            │  Веб (браузер)     │
        └─────────┬──────────┘            └─────────┬──────────┘
                  │  REST /api/*  +  SSE /api/events│
                  └───────────────┬────────────────┘
                                  ▼
                       ┌──────────────────────┐
                       │  Сервер BankInvest   │
                       │  Node.js + mssql     │
                       └──────────┬───────────┘
                                  │ TDS (порт 1433)
                       ┌──────────▼───────────┐
                       │  Microsoft SQL Server│
                       │  база BankInvest     │
                       │  usp_BuyListing,     │
                       │  usp_UpdatePrices    │
                       └──────────────────────┘
```

## 1. Что нужно установить

* **Microsoft SQL Server** — хранилище данных. Достаточно бесплатного **SQL Server Express**
  (SQL Server 2017 или новее) вместе с **SQL Server Management Studio (SSMS)**.
  Скачать: <https://www.microsoft.com/sql-server/sql-server-downloads>, SSMS — отдельно, с той же страницы.
* **Node.js 18 или новее** — сервер. Скачать: <https://nodejs.org> (подойдёт LTS 22 или 24).
  Драйвер SQL Server `mssql` ставится один раз командой `npm install`.
* **.NET 8 SDK** — только если нужна десктопная версия: <https://dotnet.microsoft.com/download/dotnet/8.0>

Проверить, что всё на месте:

```bash
node -v          # v18.0.0 или выше
dotnet --version # только для десктопа
```

Проверить, что SQL Server запущен:

```powershell
Get-Service | Where-Object { $_.Name -like 'MSSQL*' }   # State должно быть Running
```

## 2. Настройка SQL Server (один раз)

### 2.1. Включить TCP/IP и SQL-аутентификацию

1. **SQL Server Configuration Manager** → «Сетевая конфигурация SQL Server» → протоколы для
   `MSSQLSERVER` → **TCP/IP: Включено**, в свойствах (вкладка «IP-адреса») порт **1433**.
2. SSMS → правая кнопка на сервере → «Свойства» → «Безопасность» → режим проверки подлинности
   **«SQL Server и Windows»**.
3. Перезапустить службу SQL Server (например, `Restart-Service MSSQLSERVER` от администратора).

### 2.2. Создать логин для приложения

В SSMS (в базе `master`):

```sql
CREATE LOGIN bankinvest WITH PASSWORD = N'ВашНадёжныйПароль', CHECK_POLICY = OFF;
GO
```

Права выдаются после создания базы (шаг 2.3):

```sql
USE BankInvest;
CREATE USER bankinvest FOR LOGIN bankinvest;
ALTER ROLE db_datareader ADD MEMBER bankinvest;
ALTER ROLE db_datawriter ADD MEMBER bankinvest;
ALTER ROLE db_ddladmin   ADD MEMBER bankinvest;   -- нужно только если сервер сам создаёт таблицы
GO
```

### 2.3. Создать базу и объекты

Если у вас уже есть восстановленный `BankInvest.bak` — база и данные уже на месте, шаг можно
пропустить (сервер только добавит отсутствующую таблицу `Sessions` и процедуры).

Если базы нет, есть два равнозначных пути:

**Способ А — скриптами в SSMS** (как вы делали раньше): откройте и выполните по очереди
`db\schema.sql`, затем `db\seed.sql`. Выбирать базу в списке сверху **не нужно** — файлы
сами делают `USE BankInvest`, а `schema.sql` ещё и создаёт базу, если её нет:

```sql
-- так выглядит начало db\schema.sql (это уже внутри файла)
IF DB_ID('BankInvest') IS NULL CREATE DATABASE BankInvest;
GO
USE BankInvest;
GO
```

`schema.sql` пересоздаёт процедуры через `DROP PROCEDURE` + `CREATE PROCEDURE`, поэтому
работает на любой версии SQL Server (включая 2014 и старше) и его можно запускать повторно.

**Способ Б — дать серверу сделать всё самому:** просто запустите его (шаг 3) — при первом старте
он выполнит `db/schema.sql`, а если база пустая, то и `db/seed.sql`.

### 2.4. Указать параметры подключения

Переменные окружения (или файл `server/.env`, он не попадает в git):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `MSSQL_SERVER` | `localhost` | хост, можно с портом: `localhost,1433`; для именованного экземпляра — `MSSQL_INSTANCE=SQLEXPRESS` |
| `MSSQL_DATABASE` | `BankInvest` | имя базы |
| `MSSQL_USER` | — | SQL-логин приложения (`bankinvest`). Для локального SQL Server задайте обязательно вместе с `MSSQL_PASSWORD` |
| `MSSQL_PASSWORD` | — | пароль логина |
| `MSSQL_ENCRYPT` | `false` | `true`, если сервер требует шифрование |
| `MSSQL_TRUST_CERT` | `true` | доверять самоподписанному сертификату |
| `BANKINVEST_CONNECTION` | — | полная строка подключения, перекрывает всё выше |
| `BANKINVEST_AUTO_SCHEMA` | `1` | `0` — не создавать таблицы автоматически |
| `BANKINVEST_AUTO_SEED` | `1` | `0` — не заливать демо-данные в пустую базу |

Логин приложения создаётся в SSMS один раз (в базе `master`, под администратором):

```sql
CREATE LOGIN bankinvest WITH PASSWORD = N'ВашНадёжныйПароль', CHECK_POLICY = OFF;
GO
USE BankInvest;
GO
CREATE USER bankinvest FOR LOGIN bankinvest;
ALTER ROLE db_datareader ADD MEMBER bankinvest;
ALTER ROLE db_datawriter ADD MEMBER bankinvest;
```

Если логин уже существует (ошибка 15025 «уже существует»), смените пароль вместо создания:

```sql
ALTER LOGIN bankinvest WITH PASSWORD = N'ВашНадёжныйПароль';
GO
```

Для изменения процедур при автосоздании схемы логину нужна ещё роль `db_ddladmin`
(если схему вы создаёте в SSMS вручную — не нужна):

```sql
ALTER ROLE db_ddladmin ADD MEMBER bankinvest;
```

Windows, PowerShell:

```powershell
setx MSSQL_USER bankinvest
setx MSSQL_PASSWORD "ВашНадёжныйПароль"
# затем перезапустите консоль
```

Linux/macOS:

```bash
export MSSQL_USER=bankinvest MSSQL_PASSWORD='ВашНадёжныйПароль'
```

### 2.5. Проверить подключение

```bash
cd server
npm install      # один раз: ставит драйвер mssql
npm run db:check # проверяет связь, таблицы и процедуры
```

Ожидаемый результат: `Подключение : OK`, `Таблицы : все 13 на месте`,
`Процедура : usp_BuyListing — есть`, `usp_UpdatePrices — есть`.

## 3. Запуск сервера (это первый шаг всегда)

```bash
cd server
npm install      # один раз
npm start
```

или двойным щелчком по **`start-server.bat`** в корне проекта (Windows),
либо `./start-server.sh` (Linux/macOS).

**Самый быстрый способ увидеть обе версии сразу:** двойной щелчок по **`start-all.bat`**
(или `./start-all.sh`) — он запустит сервер, дождётся его готовности, откроет веб-версию
в браузере и затем запустит десктопное приложение.

В консоли появится:

```
────────────────────────────────────────────────────────────────
  BankInvest server запущен / started
────────────────────────────────────────────────────────────────
  Веб-версия      : http://localhost:8787/
  REST API        : http://localhost:8787/api
  Проверка связи  : http://localhost:8787/api/ping
  База данных     : SQL Server, localhost,1433/BankInvest (создана с демо-данными)
────────────────────────────────────────────────────────────────
  Доступы: admin/admin123 (админ), employee/emp123 (сотрудник),
           client/client123 (клиент), 100200300/client123 (предприятие по УНП)
────────────────────────────────────────────────────────────────
```

* **Веб-версия**: откройте <http://localhost:8787/> в браузере.
* **Проверка**: <http://localhost:8787/api/ping> должен вернуть JSON с `"ok": true`.
* При первом запуске на пустой базе сервер сам создаёт таблицы и заливает демо-данные:
  18 бумаг с историей цен (почасовой за 60 суток + ежедневной за ~6 лет), 12 клиентов,

**Демо-доступы**

## 4. Запуск десктопной версии

В отдельном окне терминала, из корня проекта:

```bash
dotnet run
```

(или откройте `BankInvest.csproj` в Visual Studio 2022 и нажмите F5 — файл `.sln` не обязателен).

Что важно знать:

* Десктоп при старте **проверяет связь с сервером**. Если сервер не запущен — появится окно
  с адресом сервера, подсказкой «запустите server: npm start» и полем, где адрес можно изменить.
* Пока приложение не подключилось к серверу, данные оно не показывает: **сервер — единственный
  источник данных** для обеих версий. В этом и смысл — иначе совместная работа невозможна.
* Сессия запоминается: после перезапуска приложения вход не требуется (кнопка «Выход» сбрасывает сессию).

### Как указать адрес сервера на другом компьютере

Три способа (по приоритету):

1. Переменная окружения `BANKINVEST_SERVER`, например `set BANKINVEST_SERVER=http://192.168.1.50:8787`
2. Файл `%AppData%\BankInvest\server.txt` (в нём просто адрес, одна строка)
3. Окно «Сервер BankInvest», которое появляется при недоступности сервера — там адрес можно ввести и сохранить.

## 5. Совместная работа: как проверить, что всё правильно

1. Запустите сервер (`npm start`) и десктоп (`dotnet run`).
2. В браузере откройте <http://localhost:8787/> и войдите как `190456789` / `client123`
   (вкладка **ID организации**).
3. В приложении войдите как `employee` / `emp123` (вкладка **ID пользователя**), зайдите в
   **Портфели**, выберите клиента «ООО «БелТехСервис»» (УНП 190456789).
4. В браузере: **Мои активы → Купить** → выберите предложение и купите, например, 10 бумаг.
5. В десктопе в течение секунды раздел обновится — новая бумага появится в портфеле, а в
   **Транзакциях** будет операция. (В вебе справа сверху горит зелёная точка «live».)
6. Откройте SSMS и проверьте ту же запись в базе:

```sql
USE BankInvest;
SELECT TOP 5 t.Id, c.Name AS Client, s.Symbol, t.Type, t.Quantity, t.Price, t.Commission, t.Status, t.[Date]
FROM Transactions t
JOIN DepoAccounts d ON d.Id = t.DepoAccountId
JOIN Clients c ON c.Id = d.ClientId
JOIN Securities s ON s.Id = t.SecurityId
ORDER BY t.Id DESC;
```

Покупка, сделанная в вебе, и сделка, сделанная в десктопе, выглядят одинаково — обе прошли через
`usp_BuyListing` и обе лежат в одной таблице `Transactions`.

Обратное направление работает так же: купите что-то в десктопе — обновится открытая страница веб-версии.

Технически это server-sent events (`/api/events`): сервер рассылает всем подключённым клиентам
событие `changed` (кто и что изменил) и `prices` (обновились котировки).

## 6. Настройки сервера

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8787` | порт. Пример: `set PORT=9000` (Windows) / `PORT=9000 npm start` |
| `HOST` | `0.0.0.0` | интерфейс. `0.0.0.0` — доступ с других машин, `127.0.0.1` — только локально |
| `MSSQL_SERVER`, `MSSQL_DATABASE`, `MSSQL_USER`, `MSSQL_PASSWORD` | см. раздел 2.4 | подключение к SQL Server |

Полезные команды (в папке `server`):

```bash
npm start        # запуск сервера
npm run dev      # запуск с авто-перезапуском при изменении кода (node --watch)
npm run db:check # проверить подключение, таблицы и процедуры (ничего не меняет)
npm run db:init  # создать/обновить схему и, если база пуста, залить демо-данные
npm test         # 11 интеграционных тестов на отдельной базе BankInvestTest
```

`npm test` требует доступного SQL Server и создаёт отдельную базу `BankInvestTest`
(её имя меняется переменной `MSSQL_TEST_DATABASE`); рабочая база `BankInvest` не затрагивается.

### Доступ с других компьютеров / телефона

Сервер по умолчанию слушает `0.0.0.0`, поэтому с другой машины в той же сети достаточно открыть
`http://<IP-сервера>:8787/`. Если не открывается — разрешите порт в файрволе:

```powershell
# Windows, PowerShell от администратора
New-NetFirewallRule -DisplayName "BankInvest 8787" -Direction Inbound -LocalPort 8787 -Protocol TCP -Action Allow
```

Для доступа через интернет ставьте перед сервером reverse proxy с HTTPS (nginx, Caddy, IIS ARR):
`Caddy` достаточно строки `bankinvest.example.com { reverse_proxy 127.0.0.1:8787 }`, и HTTPS
выдаётся автоматически. Обратите внимание: у сервера нет TLS «из коробки», для внешнего доступа
HTTPS обязателен, а сам сервер закройте файрволом от прямых подключений.

**Важно про SQL Server и сеть:** порт 1433 наружу открывать не нужно и опасно. Сервер BankInvest
ходит в базу по локальному адресу (`localhost,1433`), а клиенты (телефон, второй компьютер)
обращаются только к порту 8787.

Если SQL Server стоит на другой машине, укажите её адрес: `MSSQL_SERVER=192.168.1.10,1433`
и разрешите 1433 в файрволе **только для этого компьютера**.

## 7. Где данные

* Данные лежат в **SQL Server**, база `BankInvest` — та же схема, что была у десктопного приложения:
  `Clients`, `DepoAccounts`, `Securities`, `PriceHistory`, `Holdings`, `Listings`, `Transactions`,
  `Users`, `InvestmentProjects`, `AuditLog`, `DepositCertificates` + служебная `Sessions` (токены входа
  сервера; в исходной базе её не было, сервер создаёт её сам).
* **Правила торговли живут в базе**: покупка по предложению выполняется процедурой
  `usp_BuyListing` (одна транзакция, блокировка `UPDLOCK, HOLDLOCK`, комиссия 0,5 % с каждой стороны,
  проверки `ERR_OWN` / `ERR_QTY` / `ERR_SELLERQTY`), котировки «тикают» через `usp_UpdatePrices`
  (раз в минуту сервер вызывает её — так же, как раньше делал таймер десктопа).
* Резервная копия — обычный бэкап SQL Server:
  ```sql
  BACKUP DATABASE BankInvest TO DISK = N'D:\Backup\BankInvest.bak' WITH INIT;
  ```
  Восстановление — SSMS → «Восстановить базу данных» → «Устройство» → файл `.bak`.
* Файл `BankInvest.bak` в корне репозитория — архив исходной базы. Если его восстановить, сервер
  увидит существующие таблицы и данные и ничего не перезапишет: пропустит `seed.sql`, добавит только
  отсутствующие объекты (`Sessions`, процедуры, индексы).

## 9. Частые вопросы

**Нужен ли SQL Server?** Да, это единственное хранилище данных. Но **напрямую к базе десктоп не ходит**:
и он, и веб обращаются к API сервера, а сервер — к SQL Server. Именно поэтому два приложения работают
совместно и видят одни и те же данные.

**Можно ли посмотреть данные в SSMS?** Да, это те же таблицы. Запросы из раздела 5 показывают
свежие сделки, сделанные и из веба, и из десктопа.

**Что делать, если SQL Server не запущен?** Сервер BankInvest не стартует и печатает конкретную
причину (нет связи / неверный логин / нет прав / нет базы) с подсказкой. Быстрая диагностика:
`cd server && npm run db:check`.

**Где взять пароль от SQL Server?** Пароль `sa` или логина `bankinvest` задаётся вами при установке
SQL Server. В репозиторий пароли не попадают: они читаются из `MSSQL_USER` / `MSSQL_PASSWORD`
или из `server/.env` (файл в `.gitignore`).

**Можно ли запустить только веб-версию?** Да: `cd server && npm start` — этого достаточно.

**Можно ли запустить только десктоп?** Нет, ему нужен сервер (он показывает окно настройки адреса,
если сервер недоступен).

**Почему Node.js, а не ASP.NET?** Сервер использует один пакет — `mssql` (официальный драйвер
Microsoft), запускается одной командой на любой ОС, а веб-версию он же и раздаёт. Если для вашей
инфраструктуры нужен именно .NET — логика сосредоточена в `src/logic.js`, а торговля вообще живёт
в процедурах SQL Server, поэтому перенос на ASP.NET не изменит ни API, ни правила.

**Как поменять тексты интерфейса?** Десктоп — `Localization.cs`; после правки пересоберите словарь
для веб-версии: `node tools/gen-i18n.js` (или отредактируйте `server/src/i18n.json` — формат тот же).

**Добавить бумагу/клиента?** Через интерфейс (сотрудник/админ) либо напрямую в SQL Server — в SSMS
или в таблицах `Securities` / `Clients` / `DepoAccounts`. Проверка: `/api/securities` или
`SELECT * FROM Securities`.
